From the <a href="http://everything2.com/e2node/Colorado%2520Linux%2520Info%2520Quest">CLIQ 2001 conference</a>   <A href="http://www.zeapartners.org/about/pauleveritt">Paul Everitt</A>(CEO of Digital Creations) headed up the Zope BOF as well as giving a speech on Zope, really a great set of presentations. Some of the high points he hit on:<BR><BR>Zope has a steep learning curve (I disagree with this and told him so) and they are trying to make it a bit easier. They are working towards componentizing more so you can really focus on learning one piece at a time.<BR><BR>They use UML modeling, which has been (as he put it) extremely interesting. The stability of UML apps is less than ideal.<BR><BR>Activestate is working on Perl embedded in Python to make Perl native in Zope. I've no idea why you'd want to use Perl once you've used Python.<BR><BR>side note: Zope is good for cacheing, PHP/Perl/JSP are not. Anything question marked is not cacheable as per the http spec, zope doesn't use them much, php/perl/jsp do. Web services with XML protocols do not work with question marking (because XML uses question marks and you can't double question mark).<BR><BR>Zope uses a built in obj database (transactional, tunable cache, hierarchical, distributable, etc) built in python w/c extensions. It doesn't suck. relational databases = stupid databases. object databases = smart databases. What will relational db do with an arbitrarily structured xml doc? Puke. In creating zope, they wanted to create a data model that matched the web. Content managers can't think in terms of relational algebra. They think in terms of Windows Explorer. I realize that the previous sentence seems a contradiction in terms, but we are talking about content managers after all. The object database is extensible (create a product for expense reports, for example). A text index is integrated w/database, on add or undo it updates index.<BR><BR>So who is Zope targeting? Users (or potential users) of Interwoven, Broadvision, Storyserver, etc. They are working on a project with BEA right now, front ending the system.<BR><BR>Hot new tool: ParsedXML - as you traverse the doc it converts each component into a persistent object to keep memory under control.<BR><BR>Coming up in Zope:<BR><BR>Documentation - New Riders book due this summer (zope for content managers, this was going to be the O'Reilly book, but the proj mgr @ ORA totally misunderstood the proper target audience and it ended up not being the type of book ORA does). Zope Dev Guide in progress Architecture streamlining more formal component model make developers the target audience rather than content managers, let devs sell the content mgrs Raise visibility enterprise zope ease learning curve implement inverted index (more efficient cache management) replace file storage with berkeley db3 system (transaction &amp; journaling engine) zeo (distributed cache, etc) In a big coup for Zope, CBS news (all their websites, national and local) are moving from storyserver/solaris to zope/va linux Python labs is taking over the ZEO engine to make it more elegant and working on a templating model for real file system support for CVS. Guido is very involved in Zope3, meaning he's going to make it easier to use your favorite editor (in his case, emacs) and things like grep.<BR><BR>Zope Page Templates are out and work, you should keep all programming out of the presentation layer (something I've been pushing for years).<BR><BR>The lecture bit was focused more on the business side of Zope. He talked about the various content management systems (and the fact that no one seems to be sure what that label means). Content Management Systems Market  (weblogic, broadvision, etc) is a mafia business, in his opinion (and I tend to agree).<BR><BR>Content management is<BR>&quot;Software for contributing, collaborating, and controlling web content&quot; -Forrester Research<BR>&quot;An empty vessel into which marketing is poured&quot; -PaulEveritt<BR><BR>Standard CMS services are: Membership Workflow Cataloging Personalization Archiving Syndication<BR><BR>This, in my opinion, is why Zope is ideal. He touched on many of the other open source CMS-y alternatives (Ars Digita, CVW, eGrail, etc) but most of them are no longer supported or are undergoing massive rewrites. One thing that I thought was very odd. He told a story about putting together a proposal for a company in Atlanta, and he ran it by a VC he knew. The VC told him to double the cost before submitting it, because if they come in lower than the company expects to pay they will lose the contract. WHAT THE HELL DO THEY TEACH IN BUSINESS SCHOOL!?!?!??! Anyway, Paul doubled the cost and won the contract and the client still said &quot;We decided to use you even though we were concerned that you came in so much below the other bids&quot;.<BR>
