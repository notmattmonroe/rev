Title: So You Want To Be A Web Developer
Date: 2002-06-06 14:52
Slug: so-you-want-be-web-developer
Category: personal
Status: published

First off, it's not nearly as glamorous as it was back in 1999. Gone are the days of 6 figure salaries for people who could spell VB right two times out of three. You have to have some degree of actual technical knowledge to get a job as a web developer these days. Companies don't have the time or money to waste on people who don't know what they are doing. Here's an example of the sorts of things you'll be asked to do as a web developer:<BR><BR>We need to be able to go to the site and get an Excel spreadsheet that shows us who has what permissions on the website. By Monday. <BR><BR>We'll come back to that.<BR><BR>If you're in a company that has a need for a web developer, you can volunteer to help out. Keep in mind that this will likely only work at small companies that don't already have some sort of web development effort or where one of the people who used to do the web work has recently left. If they are planning on leaving, ask to be trained to replace them. Can't get your foot in the door? Start small, work on projects for local businesses and learn all you can about lifecycle development (from concept to deployment, which means learning about requirements gathering, business process, design, coding, qa, domain registration, and deployment). I'll assume for this piece that you are interesting in being a web developer, and not a graphic artist. You will have to invest time and I would advise you to invest money in some good reference books as well. Reference books are the lifeblood of the developer. Coriolis and O'Reilly are kings of the hill at the moment, while HungryMinds and Wiley and a few others are also putting out some quality titles.<BR><BR><h3>The Basics</h3>Know HTML? Great. That's not enough. It's a given that you know HTML. JavaScript is necessary. You have to be able to create complex layouts using tables, CSS, and they need to be viewable in both Netscape and IE (and keep in mind that there are other browsers out their gaining in popularity every day). Become one with forms. You will use them. A lot. If you put Front Page on your resume, you will not get any calls. Trust me. Learn a real editor. If you're a more visual person, Dreamweaver is probably THE most popular choice. For the more technically minded, Homesite tends to be the editor of choice. Mac users tend to use BBEdit, unix geeks of course have many many options the most popular of which tend to be emacs or vi. You'll also need to know how to more than copy someone else's JavaScript and change the variable names. You'll primarily be using it for form validation making dynamic elements.<BR><BR>Basic familiarity with the core internet protocols: HTTP, FTP, Telnet, SSH, SSL, SMTP. Obviously, HTTP is the most important of these for a web developer. Knowing what's going on in the headers is critical if you want to get any real work done. FTP is also reasonably important, as it's most likely how you will be getting your files to the server. Telnet and SSH are your tools for managing files and processes on the server, SSH is prefered because it's secure. SSL, while not perfect, is the first line of defense in a secure site. You will notice that when you shop online files will often end in .shtml rather than .html, which is done to indicate to the user that their transaction is secure. The accuracy of that indicator is out of scope for this piece. SMTP is the standard mail protocol, which is what you would use to (for example) email a form that a user fills out on a site. You don't need to know this in depth, but you should know how to invoke the mailer on the server and create headers and send mail with it.<BR><BR>You also need to know at least rudimentary SQL (You are going to be connecting to databases if you are a professional. That's all there is to it. Access is not a web database. Oracle, DB2, MS SQL, MySQL, PostGre, and Informix are.). You haven't needed to use a database to run your family photo website, sure, but if you plan on getting paid for web work, it's going to be more complex than that. Companies dont' hire people to make brochure websites anymore, they have the receptionist do them instead. She probably uses FrontPage. You can get MySQL for free and start learning about real databases (no, it doesn't have stored procs or much in the way of locking, but it's a good start). Your local library probably has a few books on SQL, though you might pony up a few bucks and pick up the O'Reilly MySQL book.<BR><BR>You have to know at least one server side language (ASP, PHP, CF, Perl, Python, VB). Which one you choose may be determined by what you are interested in doing. If Open Source appeals to you strongly, you'll do best with PHP/Python/Perl. If you want to stick to the Microsoft Way, then it's ASP/VB. Lots of news/sports sites run Cold Fusion, though even Macromedia is pushing people towards Java App servers instead (more on this later). Note that these are very powerful languages but they are not the be all end all and the advanced jobs are still in C/Java. That being said, you can work as a web developer never learning C or Java. Server side languages handle the business logic/database connections and use HTML for the user interface. Without a server side language, the only web dev work you'll be doing is your personal web page while you're working help desk.<BR><BR>Web security. Crackers abound, and security holes as well, and writing secure applications is extremely critical. At the entry level, you should be familiar with basic security concepts such as Access Control Lists, form validation, and buffer overflows.<BR><BR>Another application you are likely to encounter in any professional development environment is version control software. The concept of version control is fairly simple: Several developers will be working on a set of files, so you check out the specific files you need to work on, make your changes, and then check them back in. The versioning part of this is that you can go back to older versions of a particular file if there is some need to (like new functionality needs to be rolled back, changes made break the system horribly, etc etc). Right now version control software is being referred to as SCM or Team Development Tools. It's version control, get over it. Popular choices are Rational, Microsoft Source Safe, PVCS, and CVS. CVS is freely available at cvshome.org.<BR><BR><h3>Advanced</h3><BR>If you really plan on being a professional, a solid understanding of software development processes and best practices are in order. Workflow, use cases, prototyping, and coding standards are all important components. You don't need to have an MBA, but you will need to know a fair amount about business process and business requirements. If there is a particular field that you already know a lot about or that you are very interested in (finance, accounting, retail, medical information, law, etc) that knowledge combined with strong technical skills can help you become a great developer.<BR><BR>Server admin is optional, but helps give you the edge in getting the job over someone who doesn't know anything about it. At least one unix-y OS is strongly recommended (Solaris, HPUX, AIX, IRIX, *BSD, Linux). Windows is a very common development platform, but keep in mind that over 50% of websites run on some version of UNIX, and over 60% run a non-Microsoft web server (mostly Apache). Note that Amazon and Google run on Linux, and eBay uses IBM's WebSphere Server.<BR><BR>A lot of sites are using C on the backend (with PHP, Cold Fusion, Perl, Python, or ASP on the front end) while more and more are employing Java Application servers such as WebSphere, WebLogic, and JRun. These are good areas to consider if you've already mastered the Basics section and want to move to the next level. You can download trial copies of these Java app servers, and you can get a free C compiler from Gnu if you want to work on the C side. There are many development tools for Java and C, some free, most not free but with trial versions available.<BR><BR>Emerging areas, such as XML and wireless technologies are other things to consider once you master the basics. XML is rapidly on it's way to becoming one of the basics that you must have, while wireless is still very much a niche. A lucrative niche for developers, but there are fewer jobs and less stability in that niche at this point relative to mainstream web development.<BR><BR>Security is a concern in every aspect of web development (from preventing credit card fraud to protecting proprietary information to making sure the server doesn't get cracked). The more you understand security, the more marketable you are, especially in this day and age. I strongly recommend Security Engineering.<BR><BR>If you plan on being an independent developer, you will need to know about hosting services (colocation and managed virtual hosting) and be able to recommend different platforms and options based on the needs of the customer (storage space, hardware requirements, bandwidth expectations, additional services, etc).<BR><BR><h3>The bottom line</h3>Real web development is complex and requires stronger skills than just pointing and clicking on a webtool on Geocities or playing around with Photoshop. For example, if your local record store says &quot;Sure, we'll pay you to build a website for us. We want people to be able to place orders online, browse our catalog, and get directions to our store.&quot; That doesn't sound too hard. And it's not. But you have to know what you're doing.<BR><BR>Oh, the request from the intro? No prob, query LDAP and DB2 through a web page that runs a python script in the back and converts the tab delimited output to excel format (role, permissions, users assigned to role) pipe to ftp to the server. 20 minutes work.<BR>
