Title: Linux -vs- Windows
Date: 2004-04-19 14:54
Slug: linux-vs-windows
Category: personal
Status: published

I moved from Red Hat Linux 8.0 to Windows XP on my computer at work just over a month ago. I haven't used Windows at all for over two years and I've never used XP before. I found Windows 2000 to be a usable and fairly stable platform, but the limitations and frustrations were enough that I continued working more and more with Linux and Mac OS and just stopped using Windows altogether. As basically a new Windows user, these are my thoughts on the major areas that I consider to be important in an operating system.<BR><BR><B>System:</B><BR>* Dell Precision 350<BR>* 2.2Ghz P4<BR>* 1G RAM<BR>* 20G Western Digital HD<BR>* AtI Radeon 64M AGP 4x<BR>* Windows XP Professional<BR><BR><B>Reference System:</B><BR>* homemade Athlon XP 2000<BR>* 512M RAM<BR>* 20G Western Digital<BR>* Nvidia 32M AGP 4x<BR>* Fedora Core Linux 1.0 (this system mirrors the Dell I had at work before I got the new XP machine as well, except that I was running Red Hat Linux 8.0)<BR><BR>I do basically the same thing on both:<BR>* email<BR>* websurf<BR>* listen to MP3s<BR>* read/write documents<BR>* basic graphics editing (crop, resize, create web graphics for navigation)<BR>* web development (Zope, JSP, Python, Java, PHP, ASP) using WebSphere Studio and boa-constructor.<BR>* burn cds<BR>* administer remote servers with SSH/SCP<BR>* convert audio from analog tape to mp3<BR><BR>For my specific tasks, it's almost a wash. My personal preference is for Linux, as I can get things done quicker in Linux than in Windows. Someone who was more comfortable in Windows than in Linux would most likely have the opposite experience.<BR><BR><B>Email: </B>I use Evolution, which I love. I bought a subscription to Ximian Desktop just to support them for the work they've done on Evolution. It is the best email client I've ever used, and if it ran on Windows I'd be using it at work as well. Linux works better for me here.<BR><BR><B>Websurfing:</B>I use Mozilla an all platforms, including OS X. Firebird is ok, but fonts are garbage and many plugins don't work very well. Wash.<BR><BR><B>MP3 listening:</B>Experience is the same on either. Slight advantage to Windows in that I can run iTunes on Windows.<BR><BR><B>Documents:</B>Open Office handles everything I've thrown at it with no problems. Same on both platforms. Wash.<BR><BR><B>Graphics editing:</B>Photoshop is of course the killer editor, but is overkill for anything I'm doing on Windows or Linux. If I have serious graphics work to do I'm on the Mac anyway. GIMP is lighter and faster than Photoshop, Photoshop is more familiar to me. Wash.<BR><BR><B>Web Development: </B>WebSphere and boa-constructor work on both platforms, so the experience is largely the same except for performance (more on that later). For quick and dirty html/css work I use bluefish on Linux and homesite on Windows. HomeSite has a slight advantage because of it's very powerful extended search and replace functionality, but I can do the same thing with awk/sed in Linux without too much hassle. Linux has an advantage for me here.<BR><BR><B>Burn CDs:</B>Surprisingly to me, Linux is the clear winner here. So far, XP has turned every CDR I've tried to burn into a coaster. I've tried several different brands of CD with no luck. It has no problems with CD-RW's, interestingly enough. Using Easy CD Creator I get good burns every time. Also, if a burn errors on a buffer underrun you have to reboot to be able to burn any more CDs. This occurs using the built-in burning software, Easy CD, or Nero. Linux using the Nautilus built-in, gtoaster, or x-cdroast has never hiccuped on me. Even when using my old 4x external USB HP CDWriter. Linux works better for me here.<BR><BR><B>SSH/SCP:</B>Putty is a great tool for doing remote shell work on Windows, but having it integral to the command line is even better in Linux. Linux works better for me here.<BR><BR><B>Convert audio from analog tape to mp3:</B>I have a lot of old bootleg tapes. Live shows from dozens of artists numbering in the hundreds of tapes. I've completed more than half the conversion, and conveniently enough did about half on Linux and half on Windows. Since I'm converting low quality audio to digital, the sound quality isn't too much of an issue. Both systems do about the same in terms of ease of converting and the process is largely identical since I use Audacity on both. Wash.<BR><BR>More generally speaking, I find Linux to be far more useable than Windows.<BR><BR><B>User Interface / User Experience</B><BR>Fonts are crap in XP. I was very surprised to see this, as they rendered quite well in Windows 2000. Of course, they're only marginally better in Linux. Mac is the only OS that handles fonts well. Icons are rendered nicely, which was also a surprise, as Windows has generally been crap for icons.<BR><BR>System management tools are much improved, but control over user experience is still very limited. Many conveniences I'm used to (fully configureable taskbars, ability to easily position things where I want them and have them stay there, truly skinnable ui, taskbar applets, etc) are either not there or are very restricted in what they can do. Or they require buying a third party app such as Object Desktop that doesn't work very well and sucks resources like crazy.<BR><BR>The uber-Program Menu with each vendor being it's own sub-menu is crap. This is probably my least favorite &quot;feature&quot; of Windows, and always has been. I used to take the time to go in and redo my menu bar to organize apps by category, but eventually gave that up, as it was frustrating to have to redo it every time I reinstalled the OS. The vendors, I'm sure, love it as it &quot;creates brand awareness&quot; and as all vendor apps are in the same place the user may (or may not) be more likely to use the same vendors tools for doing several things. It screws the users as finding the app you want to use means remembering who the publisher is as well as the program name. For your average user this is absurd. Mac pretty much bites here as well, putting all in their own folder in the Applications folder without any sort of logical ordering either. It is marginally better because you don't need to know who the publisher is to find your software, but with everything in one folder it's still a hassle. Linux is the only one who gets this right from a useability perspective.<BR><BR>I drag the Terminal app to my quicklaunch bar every time I log in. Because every time I log out it is removed. This is stupid.<BR><BR>You cannot copy files from a CD that both has spaces in the filename and lacks an extension. This type of file is very common on Macs and fairly common on Linux.<BR><BR><B>Performance</B><ul><li>When formatting a disk, the system becomes largely unsusable.<li>Disk activity heavy tasks are SLOW.<li>Doing anything at all while searching is pointless. I finished typing the previous sentence before seeing any text appear in Notepad.<li>When burning an ISO, no other apps respond.<li>Doing a search on the 20g system partition makes the system 100% unusable (keyboard doesn't respond to input)<li>WSAD is frighteningly slow</ul>Things improve noticeably when you switch the IDE chains from PIO to DMA, I'm not sure why Win doesn't do this automagically, but it's still noticeably slower than Linux was on my older 1.7Ghz P4 Dell box. I also determined that a major performance hit was McAfee AV, which is pretty useless when it makes your system unusable. Policies here require that it scan files on every access. When you are doing Java development this is simply unusable. And McAfee will turn itself back on after an hour if you disable on-access scan. Eventually I dropped into services and set the several McAfee exe's to manual start and the system has been about 40% faster than before. It's still slower than Linux.<BR><BR>The animated dog that runs on every search certainly seems to speed things up. Really. It's moving, it must be faster!<BR><BR>Another problem that I'd forgotten about is copying large numbers of files from CD to hard drive. Every once in a while Windows just decides it can't find the files it's in the middle of copying. So I have to eject the CD and reinsert it. I've had this happen many times on many Windows machines running Win98, NT4, 2000, 2003 Server, and now XP. I've never had it happen on a Mac, I've never had it happen on Linux.<BR><BR><B>Toolset</B><BR>The lack of a full featured command line interface is death to productivity. Simple things I could do with a quick command (or bash shell autocompletion) take three clicks through menus and then one or more clicks to execute. When I do use the command line, it appears to autocomplete in a random manner (sometimes it will fill in my user name, other times a coworkers when I tab in Documents and Settings). Anything involving path operations on the command line slaps double quotes around each tabbed item, requiring you to back over the end quote before continuing. The strangest part about this is sometimes you can still tab the next item, others you can't. Again there doesn't seem to be any sort of predictability.<BR><BR>Notepad, Wordpad, and Word all suck incredibly badly. There's no obvious way to do a search and replace for anything containing a carriage return. Even the most rudimentary of linux editors does this easily.<BR><BR>Installing any software not written in VB/VC is pretty much a huge pain if not impossible. Also, most software has a gui installer, which means that if I want to change the install location from the default I have to click through half a dozen file tree items to do so (if it will even let me). Much easier to type ./configure --prefix=/newpath &amp;&amp; make &amp;&amp; make install. Yes, I feel lucky ;)<BR><BR>
